# EPUB UI Test Fixture

`reader_test_book.epub` is a deterministic EPUB fixture for Android instrumentation and UI tests.

Use it for reader flows that need stable EPUB content:

- open/import EPUB through a `content://` URI
- restore reading position
- navigate with chapter anchors
- create or verify bookmarks
- search unique fixture markers
- exercise highlight and CFI-related flows

The generated EPUB is stored at:

`app/src/androidTest/assets/epub/reader_test_book.epub`

The source files live in:

`app/src/androidTest/fixtures/epub/reader_test_book`

Regenerate the EPUB after editing the source:

```powershell
python app/src/androidTest/fixtures/epub/build_reader_test_book.py
```

Tests should copy the asset from the instrumentation context, not the target app context:

```kotlin
val testContext = InstrumentationRegistry.getInstrumentation().context
testContext.assets.open("epub/reader_test_book.epub")
```

Current basic UI coverage using this fixture lives in:

`app/src/androidTest/java/com/aryan/reader/epubreader/EpubReaderScreenTest.kt`

## Narration

Chapters one and two are narrated, so EPUB 3 media overlay flows can be tested against a real book:

- `OEBPS/mo/chapter-01.smil` — three `par`s over `chapters/chapter-01.xhtml`, anchored to
  `opening-paragraph`, `position-target-alpha` and `highlight-target-bravo`.
- `OEBPS/mo/chapter-02.smil` — **two** `par`s over `chapters/chapter-02.xhtml`, anchored to
  `search-target-delta` and `bookmark-target-echo`.
- `OEBPS/audio/chapter-01.wav` (4.5 s, three 1.5-second clips) and `OEBPS/audio/chapter-02.wav`
  (3.0 s, two clips), *generated by the builder* rather than committed: they are written straight
  into the zip, so the source tree stays text and the byte-for-byte output stays reproducible.
- `OEBPS/package.opf` — `media-overlay` on both narrated manifest items, the SMIL and audio items,
  and the `media:duration` / `media:narrator` (`Fixture Narrator`) / `media:active-class` metadata.

The two narrated chapters have *different clip counts* on purpose. That difference is what a UI test
uses to prove narration continued into the next chapter rather than restarting the one it was in: the
narration bar's position label goes from `1 / 3` to `1 / 2`.

Chapter three is deliberately un-narrated, and so are the covers and colophon a real book has between
its chapters: a book that narrates some of its spine items and not others is the common shape, and it
is the shape that catches a reader which assumes the overlay list lines up with the spine — and the
one that lets a continuation test assert the run *ends* instead of inventing narration.

`EpubMediaOverlayParsingTest` asserts this fixture parses into that index, on the JVM, so a
regenerated fixture that stops narrating fails fast rather than as a UI test that cannot find a
narration button.

Stable markers intentionally embedded in the book:

- `POSITION_TARGET_ALPHA`
- `HIGHLIGHT_TARGET_BRAVO`
- `CFI_TARGET_CHARLIE`
- `SEARCH_TARGET_DELTA`
- `BOOKMARK_TARGET_ECHO`
- `POSITION_TARGET_FOXTROT`
- `ANNOTATION_TARGET_GOLF`
- `CFI_TARGET_HOTEL`
